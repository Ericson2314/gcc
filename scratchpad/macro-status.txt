# STATUS OF EVERY PROBED MACRO.  The score is over STATUSES, never over the
# arms that happen to survive.
#
#   UNCONVERTED        scored by macro-probe.sh (INT/STR/EXP).  Absence of the
#                      macro from both bases scores FAIL, not "absent".
#   CONVERTED_SUPPLY   routed through a targetm hook, but the back end still
#                      spells the macro -- that IS how it supplies the hook.
#                      Keeps its header arm AND gains a TAB arm; both scored.
#   CONVERTED_CDATA    a (c-DATA) macro: the NAME survives and is still spelled
#                      everywhere, but defaults.h redirects it to a per-config
#                      slot, so in BOTH bases' header contexts it now expands to
#                      the same target-neutral text.  The header arm therefore
#                      stops measuring the macro's VALUE and starts reporting
#                      agreement about the redirect -- which flipped four
#                      aarch64 arms FAIL -> PASS for entirely the wrong reason
#                      on the first Stage 2 run.  So the header arm is RETIRED
#                      and the TAB arm is mandatory, by the same mechanical
#                      check as CONVERTED_GONE.  This status exists because the
#                      original two covered arms that DISAPPEAR and not arms
#                      that turn green.
#   CONVERTED_REGS     the register-vocabulary form of CONVERTED_CDATA, and it
#                      exists for the same reason: three aarch64 arms flipped
#                      FAIL -> PASS when ecad6abf6ae landed, and every one of
#                      those passes said only "both header contexts now agree
#                      that this name is target-neutral".
#                        FIRST_PSEUDO_REGISTER and N_REG_CLASSES became the
#                      compile-time UNION width, which is DELIBERATELY the same
#                      number in every consumer translation unit -- it is the
#                      layout of target_hard_regs/target_regs/target_ira/
#                      target_ira_int.  REGNO_REG_CLASS became a call through
#                      targetm_regs.  In all three cases the per-base fact moved
#                      to a RUN-TIME datum, so the header probe cannot see it
#                      any more and its agreement is not evidence of anything.
#                      Header arm RETIRED, TAB arm mandatory, by the same
#                      mechanical check as CONVERTED_GONE.
#                        The status is separate from CONVERTED_CDATA because the
#                      two are checked differently: CONVERTED_CDATA's redirect
#                      is `#define M (targetm_cdata.', this one's is a read of
#                      MULTI_TARGET_UNION_* or of targetm_regs.  One status
#                      covering both would need a completeness check that
#                      accepted either, i.e. one that is satisfied by the wrong
#                      redirect.
#   CONVERTED_GONE     routed through a hook and the macro is deleted from the
#                      back ends.  The header arm is retired and a TAB arm
#                      MUST exist in tab-probe.sh, or macro-probe.sh aborts.
#
# A macro may move UNCONVERTED -> CONVERTED_* only in the same change that adds
# its TAB arm.  macro-probe.sh enforces that mechanically against
# tab-probe.sh's TAB_MACROS line; it is not an invariant anyone has to remember.
#
# ---------------------------------------------------------------------------
# SIXTEEN MACROS BELOW SAY `UNCONVERTED' AND HAVE ALREADY BEEN CONVERTED.
# READ THIS BEFORE CONVERTING ANY OF THEM AGAIN.
#
# #108's six  STACK_BOUNDARY  PREFERRED_STACK_BOUNDARY  STACK_SLOT_ALIGNMENT
#             MINIMUM_ALIGNMENT  OUTGOING_REG_PARM_STACK_SPACE
#             FUNCTION_ARG_REGNO_P
# #123's four INCOMING_STACK_BOUNDARY  MAX_STACK_ALIGNMENT
#             MAX_SUPPORTED_STACK_ALIGNMENT  SUPPORTS_STACK_ALIGNMENT
# #124's two  ELIMINABLE_REGS  INITIAL_ELIMINATION_OFFSET
# #125's one  Pmode
# #126's three DEBUGGER_REGNO  DWARF_FRAME_REGNUM  DWARF_FRAME_REGISTERS
#
# #126's THREE ARE THE DWARF REGISTER-NUMBERING CLOSURE, and they are recorded
# as a group because converting the first without the third would have been a
# regression dressed as a fix.  `DWARF_FRAME_REGISTERS' is the BOUND that
# dwarf2cfi.cc:302 tests the numbering against; with the numbering per base and
# the bound still i386's 17, every aarch64 DWARF register above 16 would have
# been dropped from the register-size table -- quieter than the SIGKILL being
# fixed.  `DWARF_FRAME_REGNUM' is separate from `DEBUGGER_REGNO' because
# defaults.h:560 derives it with a `#ifndef' that the PRIMARY answers, and
# cygming.h:89 defines the two DIFFERENTLY while aarch64.h:840 defines them the
# same -- only the base's own translation unit can say which.
#
# ALL THREE ARE CALLS, so `tab-probe.sh' has no constant to read and they stay
# UNCONVERTED until they have TAB arms -- the same debt the other thirteen
# carry.  Their run-time both-sided evidence is `scratchpad/t126-guards.sh'
# ARM 2, gdb on the running cc1, one breakpoint per run, reading
# 97/16/30/97 for aarch64 against 17/4294967294/43/4294967295 for x86_64.
#
# `DEBUGGER_REGNO' AND `DWARF_FRAME_REGNUM' ARE FUNCTION-LIKE, so their header
# arms were never value comparisons in the first place and there is no
# wrong-reason flip to predict for them.  `DWARF_FRAME_REGISTERS' is a plain
# constant (17 vs 97) and IS expected to flip green for the base-B redirect
# reason -- the FIRST wrong-reason shape, the familiar one.  Retire it; do not
# bank it.
#
# `Pmode' IS THE OPTION-DEPENDENT KIND, LIKE #123's FOUR: i386's is
# `(ix86_pmode == PMODE_DI ? DImode : SImode)', so there is no constant for
# `tab-probe.sh' to read out of the running cc1 and it stays UNCONVERTED until
# it has a TAB arm.  Its run-time evidence is in `scratchpad/t125-guards.sh'.
#
# AND ITS HEADER ARM IS EXPECTED TO FLIP GREEN FOR A FOURTH WRONG REASON, which
# is worth naming because it is not the base-B redirect one.  `Pmode' resolves
# to DImode for BOTH configured bases.  So the header arm compared EQUAL VALUES
# even BEFORE the conversion, and it will keep doing so after: it has never
# been able to see this leak at all.  The leak was that shared code got
# SImode -- the primary's UNCONFIGURED DEFAULT, which is neither base's answer
# and appears in neither base's header context.  Retire it; do not read a pass
# here as the conversion working.
#
# #124's PAIR IS NOT LIKE THE OTHER TEN AND MUST NOT BE READ AS ONE OF THEM.
# `INITIAL_ELIMINATION_OFFSET' is redirected in the usual way and is
# unreadable by the header probe for the usual reason.  `ELIMINABLE_REGS' is
# POISONED, not redirected -- it is a brace initialiser, so there is no
# run-time spelling to point it at, and its eight consumers were rewritten to
# walk `mt_num_eliminable_regs ()' / `mt_eliminable_from' / `mt_eliminable_to'
# instead.  A header arm on it therefore reads a poison identifier in shared
# context and its own real table in a base context; if the next probe run
# reports anything at all for it, that is the poison being compared, never a
# value.  It is a THIRD wrong-reason shape, distinct from the redirect-vs-
# itself one, and it wants retiring on sight.
#
# All ten are redirected by `defaults.h' to `mt_*' calls and supplied per base
# from `target-cumargs.cc' (see `target-frame.h').  They are still recorded
# UNCONVERTED here ON PURPOSE, and it is the rule above doing its job rather
# than an oversight: a TAB arm is mandatory for any CONVERTED_* status, and
# `tab-probe.sh's harness reads CONSTANTS out of the running cc1.  These ten
# are CALLS -- four of #108's take arguments, and #123's four vary with option
# state -- so there is nothing for that harness to read, and inventing a
# status without an arm would be banking a pass.
#
# Their header arms are ALSO not evidence, in the direction that looks like
# good news: the probe's base-B context does not define
# MULTI_TARGET_TARGETM_BASE, so `defaults.h' redirects BOTH sides and the arm
# compares a redirect with itself.  That is why PRINCIPLES says never to quote
# aarch64's raw 8.  #123's four will do the same to four more arms the next
# time the probe runs -- a WRONG-REASON flip, to be retired and not banked.
#
# The real both-sided evidence for all ten is at run time on the linked `cc1':
#   #108  scratchpad/t108-evidence.sh   (object level)
#   #123  scratchpad/t123-guards.sh     (gdb on the running cc1, ARM 2)
#   #124  scratchpad/t124-guards.sh     (gdb on the running cc1, ARM 2:
#                                        pair 0 is 65 -> 31 for aarch64 and
#                                        16 -> 7 for x86_64)
#
# #134 ADDS `PUSH_ARGS_REVERSED' TO THAT LIST, AND ITS WRONG-REASON FLIP IS THE
# FAMILIAR base-B-redirect ONE.  It is on the board (line below says
# UNCONVERTED) and it is now redirected by `defaults.h' to
# `(mt_push_args_reversed ())'.  In the probe's base-B context
# MULTI_TARGET_TARGETM_BASE is not defined, so BOTH sides expand to that same
# text and the aarch64 arm will flip FAIL -> PASS saying only "both header
# contexts agree the name is target-neutral".  RETIRE IT; DO NOT BANK IT.  It
# stays UNCONVERTED because it is a CALL and `tab-probe.sh' reads constants.
#
# Its real both-sided evidence is BEHAVIOURAL rather than object-level, which
# is a first for this family: the macro decides the order gimplify.cc walks a
# call's arguments, so it is visible in the emitted code.
# `scratchpad/t134-order.sh' on `h (f (), g ())' at -O0, with the redirect
# injected OFF and back ON in the same build dir:
#     aarch64  OFF `bl g; bl f' (md5 0cbc679b3ec0) -> ON `bl f; bl g'
#              (md5 364bcdc7b2fc)   CHANGED
#     x86_64   OFF and ON both md5 7f363194d339   BYTE-IDENTICAL
# The x86_64 column is what separates "fixed" from "everyone now gets the same
# new answer".
#
# `INCOMING_REG_PARM_STACK_SPACE' (#134's other half) is NOT on this board at
# all -- it has no probe arm, which is UNMEASURABLE and not clean.  It joins
# the backlog of converted-without-an-arm macros, now SEVEN:
# INCOMING_FRAME_SP_OFFSET, DEFAULT_INCOMING_FRAME_SP_OFFSET, FUNCTION_MODE,
# ACCUMULATE_OUTGOING_ARGS, STACK_DYNAMIC_OFFSET, PUSH_ARGS_REVERSED (which at
# least has a header arm to retire) and INCOMING_REG_PARM_STACK_SPACE.
#
# ---------------------------------------------------------------------------
# THE EXISTENCE-MACRO PROBE SHAPE NOW EXISTS: `scratchpad/exist-probe.sh'.
#
# It is the FIFTH shape, and it is what the nine-macro converted-without-an-arm
# backlog was blocked on.  It does NOT read the running cc1.  It reads the two
# per-base OBJECTS -- `target-cumargs-i386.o' and `target-cumargs-aarch64.o' --
# which exist SIMULTANEOUSLY in one build tree because target-cumargs.cc is
# compiled once per back end with that back end's `tm.h'.  So both bases'
# answers come out side by side with NEITHER base selected and no
# `*_option_override' having run.  That is precisely the property tab-probe.sh's
# plugin cannot have, and it is why six endianness arms are stuck FAIL there:
# the plugin runs inside ONE selection, so the unselected base's thunks read the
# selected base's option storage.
#
# It scores TWO properties, and the second is the general answer:
#   A. VALUE, only when both bases' thunks compiled to a constant return,
#      against a PRE-REGISTERED table.
#   B. DISTINCTNESS, the two compiled bodies differ.  Scoreable for ALL of them,
#      including the ones property A cannot reach.
#
# MEASURED 2026-08-13 in /tmp/b-a7c-t108: 9 macros examined, 3 PASS, 0 FAIL,
# 6 unmeasurable/report-only; all 9 score DIFFER on distinctness, with the
# distinctness control scoring SAME.
#
#   REG_PARM_STACK_SPACE   i386=1 aarch64=0   PASS, predicted 1/0
#   PUSH_ROUNDING          i386=1 aarch64=0   PASS, predicted 1/0
#   PUSH_ARGS_REVERSED     i386=1 aarch64=0   PASS, predicted 1/0
#
# THE EXISTENCE BIT DISCRIMINATES EXACTLY WHERE THE VALUE ARM CANNOT.  STATE.md
# records the honest negative that a VALUE arm on REG_PARM_STACK_SPACE /
# INCOMING_REG_PARM_STACK_SPACE cannot tell the two bases apart on this pair,
# because `ix86_reg_parm_stack_space' returns 0 for SysV and aarch64's absence
# also produces 0 -- "correct by luck".  1 vs 0 is not luck.  That is the whole
# argument for the shape.
#
# STILL UNMEASURABLE, AND THE REASON IS NAMED RATHER THAN EXCUSED: the other six
# thunks are not constant returns.  i386's ACCUMULATE_OUTGOING_ARGS,
# INCOMING_FRAME_SP_OFFSET, DEFAULT_INCOMING_FRAME_SP_OFFSET and
# INCOMING_REG_PARM_STACK_SPACE all compile to option reads, and
# STACK_DYNAMIC_OFFSET is an option read on BOTH bases.  They are scored
# UNMEASURABLE-BY-THIS-ARM, never PASS.  Their distinctness verdict is still
# real evidence: one base reading option state while the other returns a
# constant IS a demonstrated difference between the two compiled copies.
#
# FUNCTION_MODE comes out i386=24 aarch64=27 and is REPORT-ONLY -- both are
# constants and they differ, but no prediction was pre-registered for it, so it
# is reported and not scored.  Registering one is the obvious next increment.
#
# NOTHING HAS BEEN MOVED TO A `CONVERTED_*' STATUS BY THIS.  The standing rule
# is that a macro moves only in the change that adds its arm to
# `tab-probe.sh's TAB_MACROS line, which macro-probe.sh checks mechanically.
# This is a DIFFERENT harness with a different list, and wiring it into that
# mechanical check is a separate change that should be made deliberately rather
# than as a side effect.  Three macros now HAVE a trustworthy arm; they are
# still recorded UNCONVERTED here, and that is the rule working, not an
# oversight.
# ---------------------------------------------------------------------------
