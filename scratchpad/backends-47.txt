# ONE TRIPLE PER BACK END -- 48 lines, one for each cpu_type in gcc/config/.
#
# gcc/config/ has 51 directories; mingw, vms and vxworks are OS families, not
# back ends, and config.gcc names no cpu_type for them.  stormy16 is the
# DIRECTORY name and xstormy16 is the cpu_type -- they are not the same string,
# so a census keyed on directory names and one keyed on cpu_type disagree by
# one back end unless you look.
#
# Derived from contrib/config-list.mk (the same list --enable-backends=all
# reads) by sourcing config.gcc once per triple and recording cpu_type; all
# 188 triples in that file are accepted by config.gcc, so the choice below is
# about which triple is REPRESENTATIVE, not about which one works.
#
# Where a back end has several triples the preference is linux > elf > other.
# Deliberately avoided: AIX, Darwin and VMS variants, which carry OS-specific
# breakage already on record and would attribute an OS failure to a back end.
# x86_64-pc-linux-gnu and aarch64-unknown-linux-gnu are pinned to the exact
# spellings the existing bars were measured with.
