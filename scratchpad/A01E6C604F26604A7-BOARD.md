## 6. TWO ITEMS SHARED ACROSS TARGETS — NEW, AND NEITHER IS A BACK END'S

`AB1900D5279BA137F-BOARD.md` closed on "none of the four causes is shared
between targets ... the era in which one defect explained a whole board is
over." With the per-back-end clusters gone, two target-INDEPENDENT items are
now visible above the noise, and both are the kind that a per-target reading
would file four times:

- **`gcc.dg/lto` — 53, IDENTICALLY, on aarch64, riscv64 and s390x, and absent
  from x86_64.** The same count on three targets is not three bugs. (x86_64's
  absence is itself the clue: whatever it is, the host target does not hit it.)
- **`ERROR` is 56-58 against stock's 8 on all four targets**, and 16 of each
  target's are one aborted `.exp`: `asan.exp` dies with
  `xgcc: fatal error: no target selected`. That is the driver being invoked
  without `-ftarget-config=` from inside that `.exp`, i.e. a harness/driver gap
  rather than a back end, uniform across all four, and it costs the whole asan
  directory on every target. `ERRTCL` has been 1 on every target on every board;
  this names what the 1 is.

## 8. WHAT I WOULD HAND THE NEXT AGENT, IN ORDER

1. **riscv64's `gcc.target/riscv` scan-assembler residual — 1,374.** The
   largest single item on the board by a factor of five, it COMPILES and emits
   wrong code, and no instrument in the set can see it: ICE counts, error
   counts, assembler acceptance and `readelf` all pass on it. It needs a
   both-sided assembly diff, not a log grep. `xtheadmemidx-modify*.c` (88 + 88,
   stock passes all) is the cheapest way in — two files, one extension.
2. **riscv64's `lra_assert (mode != VOIDmode)`, lra.cc:192** — 432 ICEs
   bounding 686 of the debt (33%), including all 239 of `gcc.dg/params`. A MODE
   question; do NOT file it with the register-numbering family, which is now
   closed.
3. **aarch64 function multiversioning — 256**, stock fails zero, one coherent
   feature across ~30 files.
4. **x86_64's HFmode partial-vector family — 43 of its 67.** Small, but it is
   the whole of that target's residual and it is wrong code on the one target
   where the host can check the answer directly.
5. **`gcc.dg/lto` 53, on three targets, identically.** One investigation, three
   rows; likely one defect.
6. **`asan.exp`'s `no target selected`** — 16 ERRORs per target and the aborted
   `.exp` on every board this project has taken. It is a harness/driver gap and
   it is cheap.
7. **riscv64's `align-2.c` 2^63 assembler operand** — still 20, still a
   wrong-VALUE bug on an alignment computation, still cheap, and still the class
   this project exists to remove.
