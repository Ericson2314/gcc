== BLIND SPOTS of this instrument, stated because a 0 from it is a claim
   about the instrument (PRINCIPLES section 4):
   * bare Mask(X) records with NO Var() -- they land in the SHARED
     global_options.x_target_flags and their bit numbering is per base.
     Not scanned here: 633 such records across the tree.
   * arm 3 reads gcc/config/<be>/*.h ONLY.  A macro defined in a
     generated header, or in gcc/config/*.h one level up (elfos.h et al,
     which PRINCIPLES records as 66 of 87 missed pairs in an earlier
     sweep), is invisible to it.  Upper bound, not lower.
   * arm 2 is a grep for an assignment, not a reachability proof: a var
     assigned in dead code scores OVERRIDE.

== THE BLOCKER THIS SWEEP WALKED INTO, measured, and NOT worked around
   `multi_target_select' is called from ONE place -- toplev.cc:2425, i.e. cc1.
   It is what applies each back end's own Init() values, via
   `global_options_init_<base> (&global_options_init)'
   (multi-target-select.cc:360, mt-<base>/options-init.cc).

   The DRIVER never calls it, and multi-target-select.cc's own comment says
   why it was written this way: "there are three callers of
   init_options_struct and one of them is the DRIVER, which never selects a
   target".  The conclusion drawn there -- write into global_options_init once,
   at cc1's selection -- is right for cc1 and leaves the driver with
   `{}, /* riscv_isa_spec (another back end) */' (options.cc:1726).

   That is not inert.  The driver reads target option state in at least two
   places: riscv's TARGET_COMPUTE_MULTILIB, and DRIVER_SELF_SPECS' spec
   function `riscv_expand_arch', which parses -march and needs riscv_isa_spec:

     #1 riscv_ext_info_t::default_version () const     <- gcc_unreachable
     #2 riscv_subset_list::add (char const*, bool)
     #3 riscv_subset_list::parse_base_ext (char const*)
     #5 riscv_parse_arch_string (char const*, gcc_options*, unsigned long)
     #6 riscv_expand_arch (int, char const**)
     #7 handle_spec_function (char const*, bool*, char const*)
    #12 do_self_spec (char const*)
    #13 driver::set_up_specs () const

   An explicit `-misa-spec=20191213' on the driver's command line does NOT
   help: the driver does not decode target `-m' options into its own
   global_options, so the Init is the only source there is.

   This is a DESIGN question (PRINCIPLES 2b), not a bug to patch: it decides
   whether, and how, the driver selects a base.  Reported rather than resolved.
